The default index path is the same sibling `FROG/Examples/index.v1.json`.
A missing, invalid or empty index fails before writing any documentation.
Tests use isolated temporary fixtures; they never create a replacement index
in the canonical corpus.

## Generated files and boundaries

- `docs/examples/index.md` and `docs/examples/<id>.md`: explanations, exact
  expected values, mode, profile, backend requirements and download links.
- `docs/reference/studio-draft-examples.md`: the distinction between the
  Studio Draft envelope and public FROG Source, with no implicit conversion.
- `assets/examples/index.v1.json`: the unchanged input index, also read by
  the existing documentation search.
- `assets/examples/<original-relative-path>`: actual `.frog` and declared
  dependencies, retaining their relative layout.
- `assets/examples/LICENSE`, optional `NOTICE`: the canonical corpus
  repository's license and notices.
- `assets/examples/.export-owned.json`: generated-file ownership and hashes
  only; it is not an example or semantic registry.

Only `.frog` dependencies and the declared
`Native/lib/frog-example-native-library.dll` are currently admitted for
redistribution. The latter requires the existing C source, header, CMake
recipe and README alongside it. Other libraries, archives, developer SDKs
and private preparation packs are refused. Personal absolute paths and
private source URLs are refused, including embedded paths in binary data;
they are never silently removed from the copied file.

Before deleting obsolete example output, the exporter checks its previous
ownership record, confined path and exact hash. Unknown files remain alone;
locally edited obsolete output causes an explicit error. Resolved output
paths cannot redirect through a link. A retained path whose spelling changes
only by case is not unlinked when both names identify the same physical file,
as on Windows; its previous ownership hash is still checked. `--check` compares all generated bytes
and links without writing, deleting or repairing files. Existing function
page and icon export rules remain in the same exporter.
